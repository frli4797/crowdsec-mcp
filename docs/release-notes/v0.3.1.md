# Release Notes: v0.3.1

## Summary

`v0.3.1` adds prepare-only scenario simulation command generation and improves CI cache behavior for faster, cleaner validation and image builds.

## Added

- Added `enable_scenario_simulation(scenario, reason, duration?, execute=false)` to prepare an audited `cscli simulation enable <scenario>` command for manual review.
- Added `disable_scenario_simulation(scenario, reason, execute=false)` to prepare an audited `cscli simulation disable <scenario>` command for manual review.

## Changed

- Upgraded direct GitHub Actions cache usage to `actions/cache@v5` for Node.js 24 compatibility.
- Keyed cached Python virtualenvs by the resolved Python patch version.
- Split Docker runtime/build dependency installation from source installation so code-only image builds can reuse expensive dependency layers across architectures.

## Fixed

- Reduced repeated dependency installation during multi-architecture Docker builds when only application source files change.

## Security And Safety

- CrowdSec-only MCP boundary is unchanged.
- Scenario simulation tools validate one scenario name and require a human-readable reason.
- Scenario simulation tools remain prepare-only and return `executed=false`; the MCP does not execute CrowdSec mutations.
- Existing IP write actions remain single-IP, prepare-only, and audited.

## Upgrade Notes

- Update deployments to use `ghcr.io/frli4797/crowdsec-ops-mcp:0.3.1` after the image is published.
- Existing MCP configuration variables remain compatible.
- Scenario simulation tools prepare local `cscli` commands for operator review; they do not require additional LAPI mutation permissions.
