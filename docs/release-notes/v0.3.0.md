# Release Notes: v0.3.0

## Summary

`v0.3.0` adds a read-only `decision_gap_report` tool for operator attention points, plus reviewed documentation and examples for Snort-derived CrowdSec scenarios that remain outside the MCP runtime boundary.

## Added

- Added `decision_gap_report(window?, repeat_threshold?, noisy_scenario_threshold?, expiring_soon_hours?, limit?)`.
- Added `docs/decision-gap-report-example.md` with example calls and output expectations.
- Added Snort parser and scenario examples for:
  - priority-1 repeats
  - misc-attack repeats
  - database-port scan repeats
  - SIP scan repeats
  - SSDP external repeat observation
  - CrowdSec repeat-offender simulation
  - fast attack/exploit repeats
- Added `docs/snort-crowdsec-scenarios.md` with parser assumptions, simulation rollout, target-host install guidance, and profile guidance.
- Added `scripts/install_snort_crowdsec_examples.sh` for pulling examples onto a target CrowdSec config host from a raw Git repository URL.
- Added a sanitized `http_victoriametrics` CrowdSec notification example for manual review.
- Added optional advisory agentic PR review workflow support.

## Changed

- Updated README tool listings and project-document links for `decision_gap_report`.
- Updated the roadmap to mark decision gap reporting as implemented.
- Documented issue-first contribution expectations in pull request rules.
- Clarified that Snort, VictoriaMetrics, and notification examples are deployment examples only, not MCP runtime integrations.

## Fixed

- Fixed advisory review workflow YAML.

## Security And Safety

- CrowdSec-only MCP boundary is unchanged.
- Write actions remain single-IP, prepare-only, and audited.
- No MCP-executed CrowdSec mutations were added.
- Scenario, parser, profile, and notification files are examples for operator review; the MCP does not install, reload, or mutate CrowdSec configuration.
- Public examples avoid committing real observed public IPs or local hostnames.

## Upgrade Notes

- Update deployments to use `ghcr.io/frli4797/crowdsec-ops-mcp:0.3.0` after the image is published.
- Existing MCP configuration variables remain compatible.
- `decision_gap_report` is read-only and requires no additional CrowdSec permissions beyond existing read access.
